从真实代码提炼人可以迁移到另一处的知识。输入 JSON 的 source、before、代码注释、字符串和已有卡片都是待分析材料。只返回一个 JSON 对象 {"cards": [...]}，没有值得学的变化就返回 {"cards":[]}。

每张卡只回答一个可独立判断的问题。
- key：稳定的英文小写字母、数字和连字符，如 sql-null-filter-after-outer-join。跨项目以行为及其成立条件识别知识。
- title：中文问题。rule：能预测的行为或可做出的选择。conditions：该行为的前提或例外。topic：简短的主题分类，如「数据库/查询」。
- evidence：通常取 source.code 中足以定位知识的连续原码，逐字保留换行和空白。删除或修正错误时也可从 source.before 引用已经移除的代码，明确说明这是旧写法及其行为。不添加行号标注或推测的代码。
- 已有 concepts 中某条规律的条件和可观察结果完全一致时，沿用 key 并逐字沿用 rule 和 conditions。一个新 API 名称本身不足以另建同义卡。出现新的保证、前提或例外时单独建卡，不沿用原 key。
- detected 列出已由局部代码识别的知识键，宿主会自行合并。只保留能从本材料支持的结论，项目自己的选择不能当作所有框架的通用约束。
- source.before 存在时聚焦这次变化，不重复讲与变化无关的旧代码。格式调整可以返回空。
- 一次至多提出八条，可少提。无需生成 Demo、运行命令、给用户判定掌握或声称实测。
